    設定ファイル設計

    概要

    EC-Spokeプロジェクトにおける設定ファイルの設計方針を定義します。 環境依存の設定と環境非依存の設定を適切に分離し、セキュリティと保守性を確保します。

    envに切り出すべき項目（環境依存・機密情報）

    1. 環境によって変わる値

    アプリケーション基本設定

    • APP_ENV: アプリケーション環境（local, develop, stage, prod, testing）
    • APP_DEBUG: デバッグモードの有効/無効
    • APP_URL: アプリケーションのURL
    • APP_TIMEZONE: タイムゾーン設定

    データベース設定

    • DB_CONNECTION: データベース接続タイプ（mysql, pgsql, sqlite等）
    • DB_HOST: データベースホスト
    • DB_PORT: データベースポート
    • DB_DATABASE: データベース名
    • DB_USERNAME: データベースユーザー名
    • DB_PASSWORD: データベースパスワード

    外部サービス連携

    • MAIL_MAILER: メール送信ドライバー
    • MAIL_HOST: メールサーバーホスト
    • MAIL_PORT: メールサーバーポート
    • MAIL_USERNAME: メールサーバーユーザー名
    • MAIL_PASSWORD: メールサーバーパスワード
    • MAIL_ENCRYPTION: メール暗号化方式
    • MAIL_FROM_ADDRESS: 送信元メールアドレス

    • MAIL_FROM_NAME: 送信元表示名

    • REDIS_HOST: Redisホスト

    • REDIS_PASSWORD: Redisパスワード

    • REDIS_PORT: Redisポート

    • AWS_ACCESS_KEY_ID: AWSアクセスキーID

    • AWS_SECRET_ACCESS_KEY: AWSシークレットアクセスキー
    • AWS_DEFAULT_REGION: AWSデフォルトリージョン

    • AWS_BUCKET: S3バケット名

    • THEME: 現在のテーマ名（config/theme.phpで使用）

    2. 機密情報

    パスワード類

    • DB_PASSWORD: データベースパスワード
    • MAIL_PASSWORD: メールサーバーパスワード
    • REDIS_PASSWORD: Redisパスワード

    APIキー・トークン

    • AWS_ACCESS_KEY_ID: AWSアクセスキーID
    • AWS_SECRET_ACCESS_KEY: AWSシークレットアクセスキー
    • 各種外部サービスのAPIキー・トークン

    暗号化キー

    • APP_KEY: アプリケーション暗号化キー（Laravel標準）

    認証情報

    • 各種外部サービスの認証情報（OAuth、API認証等）

    configに固定すべき項目（環境非依存・構造的設定）

    1. 環境に依存しない固定値

    アプリケーション構造設定

    • ページネーション設定（デフォルト件数、オプション等）
    • ログ設定の構造（ログチャンネル、フォーマット等）
    • キャッシュ設定の構造
    • セッション設定の構造

    機能設定の構造

    • 機能の有効/無効フラグ（環境非依存の場合）
    • 機能のデフォルト値
    • 機能のオプション配列

    テーマ設定の構造

    • テーマの定義構造
    • テーマのデフォルト設定
    • テーマのオプション配列

    2. デフォルト値が適切な項目

    • アプリケーション全体で共通のデフォルト値
    • 環境に関係なく同じ値で問題ない設定
    • 開発・本番で同じ値を使用する設定

    3. 現在使用中の設定ファイル

    config/ecspoke.php: EC-Spoke全体の共通設定

    • ログ設定（環境別のデフォルトログレベル）
    • ページネーション設定（デフォルト件数、オプション）

    config/theme.php: テーマ設定

    • 現在のテーマ名（env('THEME', 'default')で取得）

    判断フローチャート

    設定値を追加する場合の判断フロー：

    設定値を追加する場合
│
├─ 環境によって変わる？ → YES → env()に切り出す
│  └─ 機密情報？ → YES → env()に切り出す（必須）
│
├─ デプロイ時に変更が必要？ → YES → env()に切り出す
│
└─ 環境非依存で固定値で問題ない？ → YES → config()に直接記述
   └─ 構造的な設定（配列・オブジェクト）？ → YES → config()に直接記述

    判断基準の詳細

    env()に切り出すべき場合

    1. 環境によって変わる値
    2. 開発環境と本番環境で異なる値が必要

    3. ステージング環境で別の値が必要

    4. 機密情報

    5. パスワード、APIキー、トークン等

    6. リポジトリにコミットしてはいけない情報

    7. デプロイ時に変更が必要

    8. サーバーごとに異なる値が必要
    9. 環境構築時に設定が必要

    config()に直接記述すべき場合

    1. 環境非依存で固定値で問題ない
    2. すべての環境で同じ値を使用

    3. デフォルト値が適切

    4. 構造的な設定（配列・オブジェクト）

    5. 設定の構造自体が固定
    6. オプション配列、デフォルト値の配列等

    使用方法

    config() 関数の使用ルール

    アプリケーションコード内での使用

    ✅ 推奨: アプリケーションコード内では config() 関数を使用

    // ✅ 正しい: config()関数を使用
$theme = config('theme.current');
$perPage = config('ecspoke.pagination.default_per_page');

// ❌ 間違い: env()関数を直接使用
$theme = env('THEME'); // 禁止

    理由: - 設定ファイルでデフォルト値を定義できる - キャッシュの恩恵を受けられる（php artisan config:cache） - 設定の一元管理が可能

    設定ファイル内での使用

    ✅ 許可: 設定ファイル（config/*.php）内でのみ env() 関数を使用可能

    // ✅ 正しい: 設定ファイル内でのenv()使用
return [
    'current' => env('THEME', 'default'), // デフォルト値付き
    'database' => [
        'host' => env('DB_HOST', '127.0.0.1'),
    ],
];

    理由: - 設定ファイルは設定の集約場所として機能 - デフォルト値を設定ファイルで定義できる - 環境変数の読み込みは設定ファイル内でのみ行う

    env() 関数の使用禁止

    アプリケーションコード内での使用禁止

    ❌ 禁止: アプリケーションコード内で env() 関数を直接使用

    // ❌ 間違い: アプリケーションコード内でenv()を使用
class ThemeService
{
    public function getCurrentTheme(): string
    {
        return env('THEME'); // 禁止
    }
}

// ✅ 正しい: config()関数を使用
class ThemeService
{
    public function getCurrentTheme(): string
    {
        return config('theme.current');
    }
}

    理由: - php artisan config:cache 実行時に env() は null を返す - 設定の一元管理ができない - デフォルト値の定義ができない

    例外: 設定ファイル内のみ許可

    ✅ 許可: config/*.php ファイル内でのみ env() 関数を使用可能

    // ✅ 正しい: 設定ファイル内でのみenv()使用
// config/theme.php
return [
    'current' => env('THEME', 'default'),
];

    実装例

    設定ファイルの実装例

    config/ecspoke.php の例

    <?php

declare(strict_types=1);

// 環境別のデフォルトログレベルを取得
$env = env('APP_ENV', 'prod');
$defaultExLogLevel = match ($env) {
    'prod', 'stage', 'develop' => 'info',
    'testing' => 'debug',
    default => 'info',
};

return [
    'logging' => [
        'default_ex_log_level' => $defaultExLogLevel,
    ],

    'pagination' => [
        'default_per_page' => 50,
        'per_page_options' => [10, 20, 30, 40, 50, 100, 150, 200],
    ],
];

    config/theme.php の例

    <?php

declare(strict_types=1);

return [
    'current' => env('THEME', 'default'),
];

    アプリケーションコードでの使用例

    // ✅ 正しい: config()関数を使用
$theme = config('theme.current');
$perPage = config('ecspoke.pagination.default_per_page');
$logLevel = config('ecspoke.logging.default_ex_log_level');

// ❌ 間違い: env()関数を直接使用（禁止）
$theme = env('THEME'); // 禁止

    まとめ

    • 環境依存・機密情報: .env ファイルに定義し、config/*.php で env() を使用して読み込む
    • 環境非依存・構造的設定: config/*.php に直接記述
    • アプリケーションコード: config() 関数のみを使用（env() は禁止）
    • 設定ファイル: env() 関数の使用は設定ファイル内のみ許可

    この設計により、セキュリティと保守性を確保し、環境ごとの設定管理を適切に行います。
