    実装上の注意点

    Octane対応実装注意点

    Laravel Octane を使用する場合、常駐型ワーカープロセスにより、リクエスト間で状態が保持される可能性があります。以下の点に注意して実装してください。

    1. config() の動的変更

    ❌ 非推奨: 

    // リクエスト間で状態が保持される可能性がある
config(['theme.current' => 'new-theme']);

    ✅ 推奨: 

    // データベースから読み取る
$theme = DB::table('system_settings')
    ->where('key', 'theme.current')
    ->value('value');

// または、設定ファイルを変更してOctaneを再起動
// config/theme.php を変更 → php artisan octane:reload

    注意点: - 設定ファイル（config/*.php）を変更した場合は、Octaneを再起動する必要があります - .env ファイルを変更した場合も、Octaneを再起動する必要があります - 動的に変更する必要がある場合は、データベースに保存し、キャッシュを使用してください

    2. シングルトン・staticプロパティ

    ❌ 非推奨: 

    class MyService {
    protected array $requestData = []; // リクエスト間で保持される可能性

    public function setData(array $data): void {
        $this->requestData = $data; // 次のリクエストに影響する可能性
    }
}

    ✅ 推奨: 

    // パターン1: リクエストスコープにする
$this->app->bind(MyService::class, function ($app) {
    return new MyService; // リクエストごとに新しいインスタンス
});

// パターン2: リクエストごとにクリアする
class MyService {
    protected array $requestData = [];

    public function clearRequestData(): void {
        $this->requestData = [];
    }
}

// OctaneServiceProvider でリクエスト終了時にクリア
Octane::terminate(function () {
    app(MyService::class)->clearRequestData();
});

    注意点: - シングルトンにリクエスト固有のデータを保存しない - staticプロパティにリクエスト固有のデータを保存しない - リクエスト固有のデータは、メソッドの引数や戻り値で管理する

    3. セッション・キャッシュドライバ

    ❌ 非推奨: 

    SESSION_DRIVER=file
CACHE_STORE=array

    ✅ 推奨: 

    SESSION_DRIVER=redis
CACHE_STORE=redis

    注意点: - file ドライバは、ワーカー間で状態が共有されないため、問題が発生する可能性があります - array ドライバは、リクエスト間で状態が保持されないため、問題が発生する可能性があります - redis または database ドライバを使用してください

    4. View::share() の使用

    ⚠️ 注意が必要: 

    // 読み取り専用データは問題なし
View::share('blockRegistry', $blocks->all());

// リクエスト固有データは避ける
View::share('currentUser', $user); // ❌ 次のリクエストに影響する可能性

    ✅ 推奨: 

    // リクエスト固有データは、ビューに直接渡す
return view('page', ['user' => $user]);

    注意点: - View::share() で共有するデータは、読み取り専用で不変のものに限定する - リクエスト固有のデータは、ビューに直接渡す

    5. グローバル変数

    ❌ 絶対に使用しない: 

    $GLOBALS['user'] = $user;
global $theme;

    注意点: - グローバル変数は、リクエスト間で状態が保持されるため、絶対に使用しない - 必要なデータは、メソッドの引数や戻り値で管理する

    6. ミドルウェアの状態

    ❌ 非推奨: 

    class MyMiddleware {
    private $state = []; // リクエスト間で保持される可能性

    public function handle($request, Closure $next) {
        $this->state['user'] = $request->user();
        return $next($request);
    }
}

    ✅ 推奨: 

    class MyMiddleware {
    public function handle($request, Closure $next) {
        // リクエスト固有のデータは、リクエストに保存
        $request->attributes->set('user', $request->user());
        return $next($request);
    }
}

    注意点: - ミドルウェアのプロパティにリクエスト固有のデータを保存しない - リクエスト固有のデータは、$request->attributes に保存する

    7. イベントリスナーの状態

    ❌ 非推奨: 

    class MyListener {
    private $processed = []; // リクエスト間で保持される可能性

    public function handle(MyEvent $event): void {
        $this->processed[] = $event->id;
    }
}

    ✅ 推奨: 

    class MyListener {
    public function handle(MyEvent $event): void {
        // リクエスト固有のデータは、メソッド内で処理
        $this->processEvent($event);
    }

    private function processEvent(MyEvent $event): void {
        // 処理ロジック
    }
}

    注意点: - イベントリスナーのプロパティにリクエスト固有のデータを保存しない - リクエスト固有のデータは、メソッド内で処理する

    8. データベース接続

    注意点: - Laravelが自動的に接続プールを管理するため、通常は明示的な接続管理は不要 - 複数のデータベース接続を使用する場合は、接続名を明示的に指定する

    9. メモリリーク対策

    設定: 

    // config/octane.php
'max_requests' => env('OCTANE_MAX_REQUESTS', 1000),
'memory_threshold' => env('OCTANE_MEMORY_THRESHOLD', 128),

    注意点: - max_requests を適切に設定し、定期的にワーカーを再起動する - memory_threshold を設定し、メモリ使用量が閾値を超えた場合にワーカーを再起動する - メモリリークの原因となるコードを避ける（循環参照、グローバル変数等）

    10. ファイルロック

    ⚠️ 注意が必要: 

    // 複数ワーカーから同時にファイルにアクセスされる可能性
File::put($path, $content);

    ✅ 推奨: 

    // パターン1: ファイルロックを使用
use Illuminate\Support\Facades\File;

File::lock($path, function () use ($path, $content) {
    File::put($path, $content);
});

// パターン2: データベースに保存
DB::table('cache')->updateOrInsert(
    ['key' => $key],
    ['value' => $value, 'updated_at' => now()]
);

    注意点: - 複数ワーカーから同時にファイルにアクセスされる可能性がある - ファイルロックを使用するか、データベースに保存する

    11. マルチテナント対応（将来予定）

    実装時の注意点: - spatie/laravel-multitenancy を使用する場合、Octaneのフックでテナントコンテキストをクリアする必要があります - OctaneServiceProvider で、リクエスト開始時・終了時に Tenancy::forgetCurrent() を実行してください

    実装例: 

    // app/Providers/OctaneServiceProvider.php
Octane::requestReceived(function () {
    Tenancy::forgetCurrent();
});

Octane::terminate(function () {
    Tenancy::forgetCurrent();
    Octane::flush();
});

    12. 設定ファイル変更時の再起動

    必須対応: - config/*.php ファイルを変更した場合は、Octaneを再起動する必要があります - .env ファイルを変更した場合も、Octaneを再起動する必要があります

    再起動方法: 

    # ゼロダウンタイム再起動
php artisan octane:reload

# または systemd を使用している場合
sudo systemctl reload octane

    注意点: - 設定ファイルの変更は、即座に反映されません - 必ずOctaneを再起動してください

    実装時のチェックリスト

    Octane環境で実装する際は、以下を確認してください：

    • [ ] config() の動的変更を使用していない
    • [ ] シングルトンにリクエスト固有のデータを保存していない
    • [ ] staticプロパティにリクエスト固有のデータを保存していない
    • [ ] セッション・キャッシュドライバが redis または database である
    • [ ] View::share() で共有するデータが読み取り専用である
    • [ ] グローバル変数を使用していない
    • [ ] ミドルウェアのプロパティにリクエスト固有のデータを保存していない
    • [ ] イベントリスナーのプロパティにリクエスト固有のデータを保存していない
    • [ ] ファイルロックが必要な場合は実装している
    • [ ] マルチテナント対応の場合は、Octaneフックでテナントコンテキストをクリアしている
